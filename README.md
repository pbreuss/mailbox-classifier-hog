# Mailbox Classifier HOG

A lightweight image-classification project for detecting whether a smart mailbox contains mail.

The project uses **Histogram of Oriented Gradients (HOG)** features together with a **Random Forest classifier**. Training and experimentation are performed in a Jupyter notebook.

This project is part of a larger Smart Mailbox setup using ESP32-CAM devices and Home Assistant.

## Purpose

The goal is to automatically determine whether something has been delivered into the mailbox.

A camera mounted inside the mailbox captures an image. The classifier analyzes the image and predicts whether the mailbox is:

* Empty
* Contains mail or another object

The result can then be used by Home Assistant for notifications, status indicators, or other automations.

## How It Works

The basic pipeline is:

1. Collect mailbox images.
2. Preprocess the images.
3. Extract HOG features.
4. Train a Random Forest classifier.
5. Use the trained model to classify new mailbox images.
6. Forward the prediction to the smart-home system.

HOG is useful here because the camera position and mailbox environment are relatively controlled, making traditional computer-vision features a good fit for the problem.

## Training

Training is performed in the Jupyter notebook:

```text
train/mailbox_random_forest_training.ipynb
```

The notebook contains the steps for:

* Loading the training images
* Preprocessing the dataset
* Extracting HOG features
* Training the Random Forest classifier
* Evaluating the classifier
* Saving the trained model

To start training, launch Jupyter from the project directory:

```bash
jupyter notebook
```

Then open:

```text
train/mailbox_random_forest_training.ipynb
```

and run the notebook cells in sequence.

## Deploying the Classifier as a Home Assistant App

The classifier runs as a **local Home Assistant App**. The application code is installed in Home Assistant, while the trained Random Forest model remains on the Synology NAS.

The resulting setup is:

```text
Home Assistant
/addons/mailbox-classifier/
        │
        │ loads model
        ▼
/media/frigate/mailbox_rf.joblib
        │
        │ physically stored on
        ▼
Synology NAS
/Volumes/frigate/mailbox_rf.joblib
```

### Why use this architecture?

The classifier consists of two different things:

1. **Application code** – the Python service that extracts HOG/color features, loads the Random Forest model and exposes the `/classify` REST endpoint.
2. **Trained model** – the `mailbox_rf.joblib` file generated by the training notebook.

These are deliberately stored separately.

The application belongs to Home Assistant because it is part of the Home Assistant automation pipeline:

```text
Mailbox closes
      ↓
Home Assistant takes snapshot
      ↓
Mailbox Classifier App
      ↓
HOG + color feature extraction
      ↓
Random Forest
      ↓
empty / occupied
      ↓
Home Assistant notification + status LED
```

The trained model, however, is stored on the Synology NAS. Home Assistant already has the NAS `frigate` directory mounted under `/media/frigate`, so the classifier can access the model without keeping another copy inside the App.

This has an important advantage when retraining the classifier: the model can be trained on another computer, copied to the NAS, and then reloaded by the Home Assistant App. The App itself does not need to be rebuilt every time the model changes.

For example, on the Mac the model is stored at:

```text
/Volumes/frigate/mailbox_rf.joblib
```

The same file is visible from Home Assistant as:

```text
/media/frigate/mailbox_rf.joblib
```

The classifier therefore uses:

```yaml
model_path: "/media/frigate/mailbox_rf.joblib"
```

This keeps **application deployment and ML model deployment independent**.

---

### 1. Connect to the Home Assistant filesystem from macOS

Home Assistant is running as a VM and exposes its filesystem through the **Samba Share** App.

On the Mac:

1. Open **Finder**.
2. Press **⌘ K** (`Go → Connect to Server`).
3. Enter:

```text
smb://192.168.0.182
```

4. Click **Connect**.
5. Log in using the username and password configured in the Home Assistant Samba Share App.
6. Open the **`addons`** share.

> Note: `192.168.0.182` is the Home Assistant VM.  
> The Synology NAS is a separate system.

---

### 2. Copy the classifier App to Home Assistant

Copy the complete `mailbox-classifier` directory into the `addons` share.

The result should look like:

```text
addons/
└── mailbox-classifier/
    ├── config.yaml
    ├── Dockerfile
    ├── app.py
    ├── run.sh
    ├── requirements.txt
    └── ...
```

Do **not** copy only `app.py`. Home Assistant needs the complete directory because `config.yaml`, `Dockerfile`, `requirements.txt` and the startup script are required to build and run the App.

Also do **not** copy `mailbox_rf.joblib` into this directory. The model remains on the NAS.

---

### 3. Store the trained model on the Synology NAS

After running the training notebook, copy:

```text
mailbox_rf.joblib
```

to the mounted Frigate share on the Mac:

```text
/Volumes/frigate/mailbox_rf.joblib
```

Because this NAS share is mounted into Home Assistant, the exact same file is available to the classifier App as:

```text
/media/frigate/mailbox_rf.joblib
```

The App configuration therefore uses:

```yaml
options:
  model_path: "/media/frigate/mailbox_rf.joblib"
  default_image: "/media/current_mailbox.jpg"
```

The App also needs access to the Home Assistant media directory:

```yaml
map:
  - media:rw
```

---

### 4. Install the local App in Home Assistant

After copying the directory:

1. Open Home Assistant.
2. Go to **Settings → Apps → App Store**.
3. Refresh/reload the App Store.
4. Find the local **Mailbox Classifier** App.
5. Install it.
6. Start it.

The first build can take some time because Python packages such as NumPy, scikit-learn and scikit-image have to be installed.

---

### 5. Verify that the model was loaded

Open the Mailbox Classifier App.

The status page should report that the model has been loaded from:

```text
/media/frigate/mailbox_rf.joblib
```

The health endpoint can also be used:

```text
GET /health
```

A successful response should look similar to:

```json
{
  "ok": true,
  "classifier": "hog_color_random_forest",
  "model_loaded": true,
  "model_path": "/media/frigate/mailbox_rf.joblib"
}
```

---

### 6. Make the classifier accessible to Home Assistant automations

Add the classifier to the `rest_command:` section of Home Assistant's `configuration.yaml`:

```yaml
rest_command:
  mailbox_classifier:
    url: "http://local-mailbox-classifier:8098/classify"
    method: POST
    content_type: "application/json"
    payload: >
      {
        "image": "{{ image }}"
      }
```

If a `rest_command:` section already exists, add `mailbox_classifier:` underneath it rather than creating a second `rest_command:` section.

Restart Home Assistant after changing `configuration.yaml`.

---

### 7. Call the classifier from an automation

After Home Assistant has taken a mailbox snapshot:

```yaml
- action: rest_command.mailbox_classifier
  data:
    image: "{{ current_image }}"
  response_variable: classifier_result
```

The returned values can then be extracted:

```yaml
- variables:
    rf_prediction: "{{ classifier_result.content.prediction }}"
    rf_occupied_probability: >-
      {{ classifier_result.content.occupied_probability | float }}
    rf_occupied_percent: >-
      {{ (classifier_result.content.occupied_probability | float * 100) | round(1) }}
```

The automation can then react to:

```text
empty
```

or:

```text
occupied
```

For example, an occupied mailbox can trigger a photo notification and switch on the mailbox status LED.

## Updating the Model After Retraining

One of the main benefits of this architecture is that retraining does **not** require rebuilding the Home Assistant App.

Train a new model on the Mac and replace:

```text
/Volumes/frigate/mailbox_rf.joblib
```

The new file automatically appears to Home Assistant as:

```text
/media/frigate/mailbox_rf.joblib
```

Then restart the Mailbox Classifier App or call:

```text
POST /reload
```

The Python application remains unchanged while the newly trained model becomes active.

In short:

```text
Change Python classifier code
        ↓
Update/rebuild Home Assistant App

Retrain Random Forest
        ↓
Replace mailbox_rf.joblib on NAS
        ↓
Reload model
```

This separation makes development, retraining and deployment much simpler.
